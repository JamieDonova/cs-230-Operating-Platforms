# cs-230-Operating-Platforms
Repository for CS 230 Operating Platforms containing my completed Software Design Document. Includes analysis of client requirements, operating platform considerations, design constraints, and rationale demonstrating understanding of OS environments and application deployment.
Summary of The Gaming Room Client and Requirements
The Gaming Room was a client seeking to expand their existing game, Draw It or Lose It, into a cross‑platform, networked application. They wanted a scalable, cloud‑friendly system that allowed multiple players to join from different devices while maintaining a single authoritative game instance. Their requirements included platform independence, secure communication, efficient resource use, and a design that could support future growth.

What I Did Well in the Documentation
I clearly identified the client’s needs and translated them into actionable design constraints. I also explained the reasoning behind each constraint, showing how the technical decisions aligned with the client’s goals. My executive summary was concise and captured the core problem effectively.

How the Design Document Helped With Coding
Working through the design document forced me to think about structure before writing any code. Defining constraints, requirements, and platform considerations made the development process smoother because I already understood how the system should behave and what limitations I needed to respect. It helped me avoid guesswork and made the code more organized.

What I Would Revise and Improve
If I revised one part, I would refine the section comparing operating platforms. I would expand the analysis with more detail about performance trade‑offs and deployment considerations. Adding clearer examples would make the comparison stronger and more useful for future development.

Interpreting and Implementing User Needs
I interpreted the user’s needs by focusing on accessibility, scalability, and consistency. The client wanted a game that worked across devices without multiple versions, so I designed the system to run from a centralized server with platform‑agnostic communication. Considering user needs is essential because the software must solve the user’s problem—not just function technically. Good design ensures the final product is intuitive, reliable, and aligned with real‑world use.

Approach to Designing Software and Future Strategies
My approach centered on breaking the problem into smaller parts: requirements, constraints, platform analysis, and architecture. I used structured documentation to guide decisions and ensure each part of the system supported the overall goal. In the future, I would continue using techniques like UML diagrams, platform comparison tables, and early architectural planning to analyze and design similar applications more efficiently.
